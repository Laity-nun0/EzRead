# 保留版式的全文翻译

论文详情和阅读器中的“保留版式翻译”生成单语与双语 PDF。新任务使用 DeepSeek API，不需要 Codex 登录；确认窗口固定地址、模型、输出上限及本篇术语种子。任务可以暂停、继续、重新翻译，也可以恢复已完成版本和未完成草稿。全文翻译与论文问答分别使用设置中的“翻译”和“问答”配置，历史兼容见 [API 使用说明](AI_API.md)。

## API 配置与术语

在“设置 → 翻译”填写 API Key；地址 `https://api.deepseek.com`、模型 `deepseek-flash`、输出上限 384K（393216 tokens）固定。思考默认关闭，开启后可选 low/high/max，默认 high。保存仅写本机，不发测试请求或联网读取模型目录；本地配置齐全不代表在线验证成功。

输出上限包含供应商可能计入的思考 token，不表示每次固定生成该数量。截断结果不提交，也不自动重试。当前新任务仅开放 DeepSeek，旧协议适配器保留本地恢复和离线回归。传输不跟随重定向、不自动切换供应商或回退 Codex；连接关闭、超时、认证或限流失败后保留已完成缓存，由用户明确继续。

密钥只保存在实际 `data/translation-api.private.json`，Windows 使用当前用户 DPAPI 保护，其他平台使用权限为 0600 的文件（不宣称加密）。该文件不进入普通设置、文献数据库、浏览器存储或文献导出；备份恢复或换电脑后需重新填写。密钥绑定供应商及 Base URL，更换地址不能沿用旧密钥；公开接口只返回是否已保存。代码不改全局环境、Codex 配置、skills 或登录文件。

确认窗口可填写本篇术语，每行 `原文=译文`，最多 500 条。新任务将冻结的人工种子转换为 BabelDOC 原生 `Glossary`，通过 `TranslationConfig.glossaries` 传入；匹配、当前批次术语表及提示词组装交给上游，不在 API 系统提示中重复注入。自动术语提取保持关闭，不增加模型请求，不发送此前整段原译文。原生匹配不区分大小写，也不采用旧版的精确词边界；仅大小写不同且译法冲突的条目在入队前拒绝，避免上游静默去重。上游表格未转义竖线，因此含竖线的条目也明确拒绝；空白沿用已有种子规范化。原文和术语内容不因匹配改写。

旧 v2 任务继续使用原有精确大小写／词边界匹配、外层术语上下文及缓存重放。旧附加术语仍只在同一原译文单元能核实时采用；冲突保留原术语，缺少既定译法提示核对，不自动改写译文或触发补译。新任务的标准数组不提供增量术语。

任务冻结初始术语种子；v3 的实际术语表包含在上游完整提示词中并参与缓存键，v2 继续按原缓存顺序重建术语上下文。修改供应商、地址、模型、输出上限或初始术语必须明确重新生成；重译可在确认窗口继承本篇已有术语并编辑。原 PDF、已提交版本与旧草稿保持可恢复。

阅读器仅显示 PDF：没有已提交版式译文时，原 PDF 占满阅读区域，不显示空译文栏或分隔条；已有版式译文时自动显示左侧原 PDF、右侧单语译文 PDF，阅读期间后台提交成功也会自动切换。两侧使用本地 PDF.js，按当前栏宽、缩放和屏幕像素密度渲染页面，提供可复制的 PDF 文字层和同步滚动。页面按可见范围加载；缩放后重新渲染，不放大低分辨率 JPEG，缩略图仍可使用缓存图片。诊断信息默认折叠，只显示简短状态，具体原因可展开核对。

“正文文本”“英文原文”“译文”切换、正文修订及修订历史入口已移除。论文笔记、阅读位置保存及原 PDF 独立窗口继续可用。当前不提供 PDF 坐标批注或修订编辑，也不会将旧正文标记自动映射到 PDF。原有正文译文与派生 PDF 分别保存；生成 PDF 不会给正文块填入新的译文。

## 上游原生流程与质量边界

新版使用 BabelDOC 0.6.4 的完整原生 LLM 管线：PDF 解析、DocLayout-YOLO 版面识别、段落与公式处理、跨页和跨栏批处理、翻译回填、排版以及单语/双语 PDF 输出。生产流程单次调用 `async_translate`，不再先 collect 再 render，不替换 LayoutParser、ParagraphFinder、StylesAndFormulas 或 Typesetting 内部方法，也不在成品上擦除区域后粘回原图。

分批直接沿用上游：普通页内加入后检查 `>200` 原文估算 token 或 `>5` 单元，最多 6 单元；页末提交余项。段落过滤、标题上下文、跨页／跨栏配对和失败后的单段恢复均由 BabelDOC 处理。原文估算 token 不包含完整提示词、术语、JSON 和输出，不代表供应商账单或上下文硬上限。全文任务保持一个 worker 串行请求，输出上限使用任务冻结配置。

800/8 分批实验及专属容量预检已移除。带 `batch_policy` 的历史实验任务须明确重新翻译，不能按普通流程继续；普通任务不会复用实验运行目录的缓存。其他任务仍以完整提示词、供应商、模型、配置和协议核对缓存身份，组件升级时使用新目录并保留旧产物。`translation-timing.json` 保留本次运行时间和缓存／请求计数，供应商历史用量不冒充本次费用。`test_pdf_layout_engine.py` 使用合成 PDF 与模拟响应检查真实上游管线；缺少独立运行时时明确跳过原生检查。

旋转页在任务副本中统一到正文的内容坐标，原文件保持只读。这里区分页面 `/Rotate` 与内容流的字形方向：BabelDOC 0.6.4 的解析页框没有完整配合旋转坐标，直接传入可能将图表裁掉；旧方案用 `remove_rotation()` 将原本水平的文字转成了上游不接受的 180／270 度字形，又可能使正文消失。偏移 CropBox 的实测还发现该接口会扩大可见页框，不能直接用于这一任务。

当前先按横排正文字符数确定 0／90／180／270 度主方向。只带页面旋转标记时，仅在副本清除标记；内容流自身旋转时，使用 [PyMuPDF `show_pdf_page`](https://pymupdf.readthedocs.io/en/latest/page.html#Page.show_pdf_page) 在可视裁切范围内矢量嵌页，送入上游的正文保持水平。翻译后使用同一原生接口逆变换单语页并恢复原页面旋转，再调用 BabelDOC 的 `PDFCreater.create_side_by_side_dual_pdf` 完成双栏。没有复制解析器、修改字形白名单、改写翻译循环或贴回图块；PDF 清理沿用上游默认值。

输入转换在逆向显示后须通过页面尺寸、文字字符及渲染外观等价检查；输出保持原可见页框与方向。双栏逐页的左右半分别与原 PDF／单语译文实际渲染对照，避免上游吞掉嵌页异常后返回尺寸正确的空白半页。结果保存在任务的 `native/pdf/rotation-dual-validation.json`。文字、图片、表格线及公式还须经过隔离完整管线检查，静态对象数量不能代替可见内容验收。

输入和输出重建保留 PDF 文档元信息及 XMP，尤其保留上游的 BabelDOC／AI 生成标记，使其重复翻译保护继续有效。内容层像素核对不包含原 PDF 的交互式注释；原文件字节及其注释保持只读。

离线旋转验收入口为 `.\.venv\Scripts\python.exe scripts/verify-pdf-rotation.py`：自动使用独立运行时、八页合成源文件和模拟响应，封锁网络，输出正文、几何、RGB 图表区域及双栏对照。产物仅写入 `work/`，已有输出目录拒绝覆盖；不调用模型、不使用真实文献库。

这解决整页四分之一转向的输入输出坐标问题，不代表支持任意字形角度。原生竖排字体不作为页面旋转投票；同页多种反向文字、斜排图注及任意倾斜字形仍受上游 IL 方向限制，可能保留原文或缺失，需要对照原 PDF。矢量嵌页不复制原 PDF 的交互式链接、控件和注释；源文件及 EzRead 自身保存的批注不受此派生转换影响，译文不替代原 PDF。

最终发布前检查旋转页：原页有至少 100 个字符而输出文字层完全为空，或整页墨迹及覆盖区域均严重消失时，保存 `rotation-output-validation.json` 并阻止提交，错误码为 `pdf_rotation_content`。原 PDF、模型响应和已有译文保留，不因该错误自动重复请求。轻微覆盖差异仍仅提示核对；检查无法证明逐字完整性，局部漏字、视觉竖排或未翻译文字仍需人工核对。该安全边界不改写上游正文、公式、分批和排版。

`pdf_layout_engine.py` 在隔离进程中继承标准 `OpenAITranslator`，将网络传输替换为共享 API 的 JSONL 通道，复用其 `(token, regex)` 公式与字体占位符。新任务使用 `{vN}` 和 `<style id='N'>…</style>`；基类的旧 `<bN>` 标记仍能读取验证，但不用于新任务。`do_llm_translate(None)` 仅回答能力探测。API 不要求引擎输出额外的 `response/terms` 包装，也不强制 JSON 对象模式：批次返回上游规定的数组，单段返回纯译文。旧包装仅供 v2 任务兼容读取；v3 人工术语由原生 Glossary 组装，标准数组不提供新增术语。连接按论文串行复用，不累计 messages、thread 或 response ID；全缓存任务不建立 API 会话。PDF 版面计算继续在本地完成。

已有 Codex 草稿与缓存继续保留，可在本地恢复，但不再按原 thread 调用 CLI。确认窗口要求明确使用当前 API 重新生成，旧任务、版本与缓存归档保留，不能混合续译。旧任务即使从队列恢复，也会在调用引擎或模型前被拒绝。

API 不启动 CLI，不读取用户级 `AGENTS.md`、记忆或技能。新建及明确重新翻译的任务保存 `protocol: babeldoc-native-v3`，使用最小数据边界系统提示，翻译和输出规则由 BabelDOC 提示词决定。旧任务缺少协议字段时按 `babeldoc-native-v2` 恢复，保留其原系统提示、术语和响应兼容；组件更新也不升级旧任务协议。v2、v3 和更旧的 `native-api-terms-v1` 缓存均不混用；未知协议在调用模型前拒绝。

新建 DeepSeek 全文任务的配置保存 `thinking: disabled`，请求明确关闭思考以减少推理消耗；旧任务不补写该字段，保持原有供应商默认。配置参与缓存身份，继续任务不能切换思考模式；需要切换时明确重新生成，已有草稿和缓存保留。其他模型功能保持原配置。

API 的外层 JSON 有效，不代表其中承载的 BabelDOC 批次数组也有效。v3 在完成供应商包络、结束状态及传输完整性检查后，保存并原样返回模型文字，不预先解包、修复内层 JSON 或要求额外 `response/terms` 包装。在隔离引擎中复用 BabelDOC 的 `_clean_json_output` 清理副本，再严格检查重复字段、非标准数值、单元数量及 ID；失败在模型通道之外抛给上游原生批次循环，进入标准单段恢复。合法代码围栏可以直接被上游清理，无需单段补试；原始响应和缓存字节不变。v2 继续保留一层额外 JSON 转义及旧包装的读取兼容。

批次组装、提示词、token 启发式和批次失败后的单段回退直接使用 BabelDOC 0.6.4 原实现，不再复制 `ILTranslatorLLMOnly.translate_paragraph`，也不关闭其默认的 same-text 回退。长度比例或原样返回可能触发上游单段请求；v3 批次内容的格式或 ID 错误可进入标准单段恢复，单段终态失败后停止后续请求并阻止发布。认证、限流、HTTP／外层 JSON 损坏、截断、拒绝和身份不符仍直接停止。恢复会产生额外模型请求，实际用量以供应商报告为准；缓存中的同一坏批次仍直接重放给上游，不付费重译整批。

`ezread/pdf_native_adapter.py` 只处理提交边界，将原始输入对象和响应直接交给上游 post 方法，不复制或改写解析输入。原生 PDF 通道区分字体包裹与公式：标准 style 字体标签可整对缺失，保留的标签须成对、ID 已知且无重复。上游自行保留能匹配的字体片段，其余文字按段落基础字体解析，不猜补字体标签、不重新请求模型；原文中的字面代码标签不作为可丢弃字体。公式 `{vN}` 的缺失、重复或新增仍拒绝，旧 b 标记和其他翻译接口保持严格契约。半边、未知或不支持的字体标记也不作为可接受降级。

每次回填后只读核对实际生成的公式对象及普通文字，防止“响应里有公式 token，但被字体片段正则吞掉，PDF 中没有公式”。不在适配器中剥除字体或重新解析来修复吞公式；检查失败回滚段落与追踪输出，交由上游标准单段回退，恢复后仍不完整则阻止发布。旧成功输出不能掩盖本次失败。只有字体降级且实际内容完整的已保存单段响应可以直接复用，并标为待核对；原始响应字节不重写。批次公式失败交给上游逐段恢复，不在缓存层反复重译整批。批次 JSON 仍拒绝重复字段和 NaN/Infinity，严格核对数量与 ID。

上游样式正则不跨行；带物理 CR/LF 的响应也原样交给上游，实际文字和公式完整时允许字体降级。段落与追踪输出保留原响应，不增加换行归一化或字体标签改写。上游仅因字体匹配不全未设置完整性标记时，须先通过实际 composition 的正文、公式与无幻觉移除检查，再记录经过 EzRead 核验的完整性结果和字体降级警告。无字体占位符的解析失败不能借此通过。审计写入 `native-translation-validation.json`。

每次执行在私有任务目录写入 `translation-timing.json`，失败或取消也保留：引擎总时间、模型请求往返累计时间（含首次连接初始化）、其余本地和传输时间及请求/复用计数。它只代表本次执行，不累计旧缓存的模型耗时；引擎结束后的字形审计不计入该总时间。离线缓存回放只能验证减少请求和本地处理，不能当作在线模型提速比例。

`ezread/pdf_native_translation.py` 管理请求与缓存。缓存键包含原 PDF 哈希、完整供应商/模型配置、上游版本、协议、完整提示词、请求参数及实际术语上下文；仅本地排版代码指纹变化不使相同请求失效。组件更新仍新建任务产物，在验证身份后复用请求响应。续译除当前目录外，还会只读检查同论文内身份匹配的历史运行目录，防止多次升级和中途暂停丢失祖先缓存；明确重新翻译的新任务不扫描历史。当前、直接前运行、其余历史依序查找，先选通过纯校验的有效回复，不让坏缓存遮住好缓存或膨胀计数。覆盖当前坏记录前保留原始字节；当前记录读锁或来源越界时禁止覆盖。`cache-sources.json` 留下历史目录的核验结果。通过 API 传输层完整性检查的响应先保存再进行原文单元校验；术语元数据错误不会丢弃合法译文。排版或发布失败保留已收到的结果。结构性失败响应独立保留；用户明确继续后只补试结构性失败请求。数字等内容疑点保留响应并进入待核对，不触发补译，不自动无限重试。`api-usage.json` 保留供应商返回的数值用量，包括命中本地缓存时原请求的记录，不能将该文件合计当成本次实际计费。

API 任务只复用同协议、完整请求及术语上下文匹配的缓存，不迁移缺少术语元数据的旧单元缓存。旧 Codex 响应不带入新 API 任务。公式/字体占位符隐藏对象可能与新版不同，因此不只按占位符名字套用旧译文，也不按片段猜接。新建任务协议为 `babeldoc-native-v3`，旧 v2 草稿继续以 v2 恢复，不跨协议复用。未主动删除文献时，旧版 PDF、文字单元及历史产物继续保留；同源草稿在组件更新后仍可恢复为暂停，确认继续时新建目录重新分析，原 PDF 变化则拒绝恢复，不查询模型目录或密钥。

质量检查与引擎分工明确：

- 翻译边界严格检查响应结构、单元 ID 和占位符对象数量；数字与疑似失败说明作为内容疑点记录，不据此中断整篇。
- 输出前读取上游跟踪记录，核验最终输出非空、最终尝试成功和占位符完整性；旧的失败历史在最终已成功恢复时只提示核对。终态错误、未完整匹配或实际移除标记不能被非空 tracker 输出掩盖。核对原文件哈希、页数、页面尺寸和双语结构，PDF 文字层字符计数差异不作为字形丢失的确定证据。
- `pdf_layout_quality.py` 检测字形碰撞和小字，阈值命中的原始失败证据保存在报告中，发布时标为待核对，保留旧版本供恢复。原生跟踪不提供所有段落的完整几何；仅对能唯一匹配源文字块的范围检查，缺失范围明确显示“需核对”，不以空检查判定通过。
- 作者名、代码等原样返回不单独作为失败；未变化的正文仍需核对。上游可能漏译短片段、错误分组或压缩字号，原生流程不等于所有论文无损。

数字核验由 `translation_numbers.py` 比较数值、倍率和常用单位量纲，其检测结果统一作为待核对提示，不决定整篇任务是否中止。相同数值可能因 PDF 粘字、上下标、范围和译法变化被解析为不同数字；同样，也不能将检测通过解释为语义正确。数字、单位、引文、编号甚至看似明确的数值变化都保留提示，请对照原文确认。缩写只使用本篇原 PDF 明确写出的定义；未知定义不猜测。私有 `numeric-reviews/` 保留完整原文、译文和原因，界面提示附带简短原译文片段。新规则复核已保存响应，待核对结果可直接复用，不改变缓存键或模型配置。

校验策略统一如下：

| 检查 | 处理 |
| --- | --- |
| 数字、单位、引文、编号差异或无法解析 | 待核对，继续排版 |
| 译文出现疑似原文残缺、无法翻译说明 | 待核对，保留响应 |
| 公式或完整字体样式对调序，对象、数量和嵌套一致 | 允许自然语序变化 |
| 长度比例或英文原样返回 | 沿用上游标准回退，结果仍需核对 |
| 空字体片段 | 待核对，不单独据此重译 |
| 原生字体标签整对缺失或合并，公式完整 | 同一响应按段落基础字体排版，提示样式降级；不补译 |
| 字体标签未配对、重复、未知或含新增不支持格式 | 保留响应；不能作为安全字体降级 |
| 批次公式占位符缺失、重复或新增 | 保留响应，由上游单段恢复；最终仍不完整则中止 |
| 回填后实际公式对象或普通文字不完整 | 回滚；恢复失败中止，不能仅凭 token 计数发布 |
| 批次 JSON/ID/输出不完整 | v3 保留原响应，由上游标准单段恢复；最终仍不完整则中止。v2 保持原边界 |
| 旧尝试曾失败，但最终尝试完整应用成功 | 待核对 |
| 最终回填失败、标记未完整应用或实际移除标记 | 中止，不以非空追踪文字冒充成功 |
| 中文字符计数、字形重叠、小字号或旋转页覆盖差异 | 待核对，原始检测报告保留 |
| 旋转原页至少 100 个字符而输出文字层完全为空，或墨迹与区域均严重消失 | 中止，保留原 PDF、响应和页面核验报告 |
| 原 PDF 归一化前后不等价 | 中止，不能把改变后的输入当作原文 |
| PDF 缺失、不可读取、页数/尺寸/双语结构不符 | 中止，不提交无效产物 |
| 源文件、模型、缓存、任务身份不符或越界路径 | 中止，防止混用或覆盖数据 |

内容提示不会自动修正译文，也不意味着已确认正确；产物标记 `needs_review`。结构、文件、任务契约失败以及上述明确的旋转页缺失条件会阻断提交。

任务分别显示本次收到的响应文字单元数（含缓存和补试返回）、已交付上游排版的数量、待核对数量、当前未通过数量，以及缓存复用和模型请求次数。整批响应有硬错误时，该批不会交付排版，但已经收到的内容仍计入并保存。上游未提供预知总量时不显示 0/0 或虚构百分比；只有产物完整核验并提交后才显示 PDF 已提交。上述检查是数值约束核验，不是译文语义正确性的证明。

表格和图内文字遵循所固定上游版本的处理，不再承诺整表冻结或可靠逐格翻译。图像、原字体公式及矢量对象由上游重建；扫描件、复杂表格和特殊字体需要独立核验。英文存在人工校订时仍阻止版式生成，以免忽略校订；原有修订和正文译文数据继续保留，当前 PDF 阅读器不提供旧正文查看或编辑入口。

本地多文献回放发现：部分复合图的矢量线条在上游重建后变浅，恢复上游默认清理参数仍未消除；页边竖排文字也可能丢失。因此即使页数、尺寸及中文字形检查通过，也不能宣称图形无损或全文质量通过。阅读时保留原 PDF 对照，诊断与失败样本独立留存，不以逐篇贴回图块掩盖上游缺陷。

## 旧全文翻译下线与数据兼容

旧 HTML 全文翻译及批量生成入口、入队和执行分支已下线；旧 `/translate`、`/pause` 请求返回 410，不启动模型。单篇全文翻译统一进入 PDF 版式确认窗口。历史未完成任务只保留草稿，不自动续译。

未主动删除文献时，保留原文块、已有译文、人工校订、批注、阅读位置、历史版本与本地未提交草稿。旧正文编辑、选区查词／翻译、段落重译和修订历史界面已移除，`reader-text.js` 已删除；保留后端存量数据、兼容 API 和浏览器原有草稿保存键，不自动应用或删除旧草稿。桌面关闭快照仍包含这些草稿，论文通用笔记仍可编辑和保存。永久删除文献会同时清除该篇记录、资源、会话与本机阅读草稿，重导不继承旧任务或对话。

版式译文 PDF 的已完成版本与未完成任务草稿仍通过版式翻译设置窗口恢复；它们与旧正文编辑草稿分别保存。此改造不把现有批注迁移为 PDF 坐标批注，也未新增 PDF 坐标批注或修订编辑。

## 独立运行时

使用固定的 BabelDOC 0.6.4、PyMuPDF 1.26.7、bitstring 4.4.0 等依赖，完整锁定清单见根目录 `requirements-pdf-layout.txt`。不升级主程序 `.venv` 或全局 Python。

```powershell
.\.venv\Scripts\python.exe scripts/setup-pdf-layout.py
```

该准备命令联网安装锁定依赖并获取上游模型和字体。运行时位于 `.deps/babeldoc/runtime/`，专用资源缓存位于 `.deps/babeldoc/home/.cache/babeldoc/`。可用性接口 `/api/pdf-layout` 只检查本地组件；翻译 worker 核验固定资源后进行本地版面分析，缺资源明确失败。PDF、图像和页面坐标不发送给版面服务；翻译文字只通过任务明确选定的通道发送。

已有经过校验的相同版本环境时，可离线准备：

```powershell
.\.venv\Scripts\python.exe scripts/setup-pdf-layout.py --seed-runtime <已安装依赖的虚拟环境> --seed-assets <包含.cache/babeldoc的专用目录>
```

只复制锁定发行包的文件及官方资源清单里的资产，不复制账号 HOME 或登录配置。准备结果记录包版本、资源大小和校验值；源码、锁定依赖清单和资产清单的指纹随任务保存。组件更新后，“继续”会创建新的版面分析与派生产物，复用原 PDF、模型配置和完整请求一致且结构校验通过的已译内容；内容待核对提示不使缓存失效。变化或新增单元须补译，不能在旧分析结果上混合排版，更换模型仍必须明确重译。

## 保存与验证

派生产物、原生请求响应与未完成批次位于实际文献库的 `library/<文献ID>/pdf-layout/<任务ID>/`。只有提交的 mono/dual PDF 和预览允许通过媒体接口访问，提示词、跟踪记录与缓存均为私有文件。模型额度受限或用户暂停时保留缓存和旧 PDF，明确继续后才重试。

已发布版本的目录保持只读；即使同组件、同模型再次继续，也新建产物目录并复用原请求缓存。新结果通过核验后才更新当前版本，排版失败不覆盖旧 PDF 文件。

普通检查使用合成 PDF、模拟模型和隔离库，不进行真实推理。`scripts/verify-pdf-layout.py` 对本地论文运行原生完整管线，可选择原文回放或精确旧缓存混合回放，并输出缓存覆盖率、实际请求数、原文回放段数、页面与质量报告。缓存未命中绝不触发模型；原文/模拟回放不能作为中文翻译质量验收。验证产物放在忽略的 `work/`，不改真实库。

`scripts/verify-api-translation.py` 使用临时文献库和真实浏览器，验证 API 设置、密钥留空保存、刷新恢复、宽窄窗口与确认入队；禁止任何 CLI 查询和远端模型请求。`tests/test_translation_api.py` 用回环 HTTP 服务验证四种协议、同连接、无历史、取消、截断和脱敏；`tests/test_pdf_api_tasks.py` 验证实际 API 传输与模拟 BabelDOC 的整合、术语重放、缓存、版本及密钥导出隔离。命令为 `.\.venv\Scripts\python.exe scripts/verify-api-translation.py`，结果位于忽略的 `work/api-translation-verification/`。这些离线检查不证明真实服务可用或译文质量通过。

`scripts/verify-pdf-channel.py` 是遗留适配器的开发诊断工具，会使用真实 CLI；它不属于日常运行路径，也不是 API 离线验收的必要步骤。

多版式验收固定包含双栏正文、复合子图、图文混合表格、行内分式和横向页面。应比较各篇论文的处理结果，保留失败样本，不能以单篇通过或上游退出码 0 宣称全部可靠。`scripts/audit-pdf-layout.py` 可继续读取旧审计产物；新任务使用 `native-text-audit.json`，部分几何覆盖须如实报告。

## 来源与许可

API 协议依据：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[OpenAI Responses 会话状态](https://developers.openai.com/api/docs/guides/conversation-state)、[Anthropic Messages](https://platform.claude.com/docs/en/api/messages/create)、[Gemini generateContent](https://ai.google.dev/api/generate-content)。通用兼容接口仅承诺实现这些已支持的请求字段，第三方网关的额外要求需另行核对。

技术路线参考 Zotero PDF2zh 的附件与外部引擎分工，没有复制 XPI 插件代码。实际接入来源为 [BabelDOC v0.6.4](https://github.com/funstory-ai/BabelDOC/tree/v0.6.4)；其 Python 发行包声明 AGPL-3.0，PyMuPDF 声明 AGPL-3.0 / Artifex 商业双许可。许可文本保留在 `assets/third-party/pdf-layout/`，完整发行包中的版权和许可文件保留在隔离运行时。

Zotero PDF2zh 插件支持旧 `pdf2zh` 与 `pdf2zh_next` 两条引擎路径，不能将某个 Zotero 环境的成功率直接等同于固定版本 BabelDOC 的行为。[插件 v4.1.7 服务端](https://github.com/guaguastandup/zotero-pdf2zh/blob/v4.1.7/server/server.py) 将配置传给外部引擎，并支持 `--disable-rich-text-translate`。[PDF2zh Next 的调用层](https://github.com/PDFMathTranslate/PDFMathTranslate-next/blob/main/pdf2zh_next/high_level.py) 同样创建 BabelDOC 配置并调用其完整翻译流程；本项目复用该分工，仍使用现有固定版本运行时，没有引入 Next 的整套服务。BabelDOC 0.6.4 本身会在单段占位符过多时禁用富文本，批次失败可进入单段回退；其段落解析也不将每个字体匹配缺项都直接提升为整篇失败。EzRead 的缓存和发布校验属于本项目额外边界，应区分可安全降级的字体样式与不可丢失的公式对象，不能额外要求所有字体包裹逐一对应。段落降级后仍显示待核对，文件成功生成不代表语义和图形无损。

模型、字体与 CMap 的具体文件和校验值由上游 BabelDOC 资产清单记录，安装后保存于 `.deps/babeldoc/runtime-manifest.json`。阅读器使用 [Mozilla PDF.js 6.4.299](https://github.com/mozilla/pdf.js/releases/tag/v6.4.299) 官方发行文件；所需模块、字体、CMap、WASM 与 Apache-2.0 等许可保存在 `static/vendor/pdfjs/`，`vendor-manifest.json` 记录发行包来源、SHA-512 及逐文件 SHA-256。所有渲染资源本地提供，不使用 CDN。项目根目录 MIT 文本不替代这些第三方组件许可。Windows 安装版按白名单提供固定运行时、公共资源、原有许可与对应源码，构建方式见 INSTALLER.md，第三方声明见根目录 THIRD-PARTY-NOTICES.md。
